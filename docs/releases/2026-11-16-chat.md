## Fix and architecture

The old browser sent `toId` while the standalone Lambda expected `to`. That Lambda also held connections in one process-local dictionary and let callers claim any account ID. Fixing the field mismatch alone would leave delivery unreliable and identity unverified.

- The browser now sends its current Cognito ID token in a WebSocket subprotocol header during `$connect`. The handler verifies signature, pool/client, expiry, verified email and SQL account/subject binding **before accepting the handshake**. It returns only the public `marido-chat` subprotocol. Tokens never enter URLs or the connection table; API request/data tracing is disabled.
- DynamoDB stores two transactional connection records: a connection lookup and an account/connection index. Strongly consistent queries support separate Lambda instances and multiple tabs. Each entry expires with the verified JWT; expiry is checked during routing/actions, independently of asynchronous TTL cleanup. Removing a connection removes both records transactionally.
- The REST message endpoint derives the sender from the verified identity and validates the recipient exists. After SQL persistence it builds a canonical event from that saved row and sends it only to the sender's and recipient's verified connections. Current SQL subject bindings are checked when selecting connections. Browser-supplied sender/routing/content frames cannot publish messages. The old `sendPrivate`, `sendPublic` and default publishing routes reject attempts and close the socket; `setName` cannot rebind an account.
- Direct contact between registered accounts keeps the existing product behavior. This release does not introduce a project/quote prerequisite for starting a conversation. Private history/read-state requests remain scoped to the signed-in participant; a third party cannot read another pair's conversation. Presence is returned only to the requester and includes only its existing contacts.
- The frontend merges server events by message ID and outgoing correlation key, retains newer live events while history loads, and reloads the active conversation on reconnect. It captures the recipient before awaiting persistence, ignores stale history/contact responses after a conversation/account switch, closes sockets on identity change and clears cached chat data on logout. No timer fabricates read receipts.

SQL remains the durable message source. Live push is best effort after persistence; a transport failure does not falsely report the database write as failed. Reconnect/history catch-up provides recovery. This is not a transactional outbox or an exactly-once delivery guarantee. New messages use server time and persisted status, ignoring caller timestamps/delivery flags. Unknown historical times render as a dash; ISO/SQL/Date/Luxon values normalize consistently. Existing list limits still apply. Attachments and a complete read-receipt UX remain outside this repair.

AWS references: [WebSocket subprotocol handling](https://docs.aws.amazon.com/apigateway/latest/developerguide/websocket-connect-route-subprotocol.html), [backend connection callbacks](https://docs.aws.amazon.com/apigateway/latest/developerguide/apigateway-how-to-call-websocket-api-connections.html), [DynamoDB expired-item filtering](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/ttl-expired-items.html) and [transaction permissions](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/transaction-apis-iam.html).

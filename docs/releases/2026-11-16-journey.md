# Registration and project workflow release — November 16, 2026

This release follows the [runtime, credentials and photos release](2026-11-16-hardening.md). All AWS resources and data are development. Commits are local; nothing was pushed.

Status: **Core workflow deployed and verified; notification email and immediate WebSocket delivery remain open.**

## Behavior

- Cognito is configured before session restoration. Refreshing an authenticated page retains the login. Signup no longer logs passwords or confirmation codes, or submits an audit write before verification.
- Project tiles resolve the assigned contractor locally instead of overwriting the signed-in contractor's store. Generated photo keys render as public S3 image URLs.
- Clients can expand **Ver ofertas**, review contractor names, prices and scope, accept an offer, and mark an assigned project completed. The UI updates from the committed server response.
- `PUT /quotes/{id}` accepts `{clientConfirmation:true, expectedVersion:<version returned by the quote read>}`. The project owner must accept the current quoted price and scope. Server-derived agreed price and project assignment commit in one transaction, locking the project before its quote. Competing acceptance gets 409; retrying the winner does not change its confirmation time. Accepted terms/deletion, reassignment/reopening, late bids and deleting projects with offers are guarded. No schema migration or new AWS route was needed.
- `GET /projects?mine=true` requires authentication and derives the filter from the verified account: client-owned projects or contractor assignments. Caller-supplied owner IDs cannot change this scope. Contractor account links now open contractor routes for messages, security, reviews and projects.
- A review requires a completed assigned project, the opposite participant as recipient, an integer rating 1–5 and nonempty text. Duplicate author/project reviews return 409. New reviews remain pending moderation.
- Bid/review forms retain drafts on persistence failure. A saved bid with a failed notification is reported as saved. Chat history loads independently of WebSocket startup; incoming conversation matching is synchronous. Chat saves before broadcast, renders one outgoing copy, reports persistence failures and no longer fabricates delivery/read receipts with a timer.

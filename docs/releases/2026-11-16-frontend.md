## Rollback procedure

Run from the FE repository with the verified AWS profile. The local snapshot is required; keep `.deployments/` available and outside Git because prior site artifacts may contain secrets.

```powershell
# Restore prior assets first; retain newer assets for cached page compatibility.
aws s3 cp '.deployments/fe-20261116T074953Z/previous/' s3://www.marido-en-alquiler.com/ --recursive --exclude 'index.html' --profile default --only-show-errors

# Then switch the entry page back.
aws s3 cp '.deployments/fe-20261116T074953Z/previous/index.html' s3://www.marido-en-alquiler.com/index.html --content-type 'text/html' --cache-control 'no-cache,max-age=0,must-revalidate' --profile default --only-show-errors

aws cloudfront create-invalidation --distribution-id EI5JEIS37I445 --paths '/*' --profile default
```

Check each command for success before continuing, wait for invalidation completion, and compare the served entry-point hash with the previous hash above. The snapshot and restore procedure are prepared; rollback was not executed. Restoring the old frontend can also restore its security defects, so assess that tradeoff before using it.
